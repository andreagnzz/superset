# Run a plan's issues from the host: a durable queue with dependencies and a cap on parallel agents

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

Reference: This plan follows conventions from `AGENTS.md`, `packages/host-service/AGENTS.md`, `packages/trpc/AGENTS.md` and `.agents/commands/create-plan.md`. It covers milestones M2 and M3 of the roadmap `plans/20261021-1400-ade-perso-roadmap.md` (written in French).


## Purpose / Big Picture

In Phase 1, `/ade:run-plan` keeps a run's state in a Claude session's context: if that session dies, the run is lost. After this plan, the host service on the VPS owns the run. The owner imports an `issues.json` (the format `/ade:plan` writes) with `superset plan import`, starts it with `superset plan run <id> --max-parallel 2`, and can close every terminal: the host starts one workspace and one Claude agent per ready issue, never more than the cap at once, with model and effort from the issue size (one size up after a failure), marks an issue done when its agent ends its turn with the `SUPERSET_WORKER_DONE` envelope, retries a blocked one once, blocks the dependents of a failed one, and picks the queue up where it was after the host restarts. `superset plan status <id>` shows every issue's state, workspace and branch.

Pull requests and stacking on push (M4) and the review loop (M5) come in later plans; here an issue ends at `done`.


## Assumptions

The VPS runs this fork's host built from `main` (M1 included), with `routing.json` linked next to `host.db`. Agents are Claude (`--agent claude`). The owner authorized going ahead without a plan-approval stop.

## Surprises & Discoveries

- Observation: a Claude hook that fires while the host is down is lost, so an agent that finished during a restart could stay `working` in the agent store forever. The transcript is written regardless. The manager now reads the transcript of an agent whose state has not changed for two minutes and acts only on an envelope for its issue.
  Evidence: found while preparing the restart test; covered by the test "reads a stale working agent's answer".

- Observation: the worker prompt contains the envelope format; with the real key in it, an agent that has not answered yet would read as done from its own prompt. The prompt writes `task: <this issue's key>`, and the reader only looks at the last `Assistant:` turn of the transcript.
  Evidence: test "workerPrompt never reads as the issue's own envelope".


## Decision Log

- Decision: keep each run in a JSON file, `~/.superset/host/<organization id>/plan-runs/<run id>.json`, not in new `host.db` tables.
  Rationale: tables need a host migration; upstream numbers its host migrations too, so every weekly sync would meet two different migrations with the same number, and hosts that ran the fork's would disagree with upstream's journal. One host process owns the files; every write goes to a temporary file in the same folder and is renamed over the old one, so a crash never leaves half a file.
  Date/Author: 2026-10-21, Claude.

- Decision: the manager takes all its effects as injected functions (launch, agent state, last answer, nudge, routing rules), on the model of `PageWatchManager`; `createApp` binds them to the real host functions.
  Rationale: the queue logic is tested with fake agents and no real waiting (`AGENTS.md`, Tests).
  Date/Author: 2026-10-21, Claude.

- Decision: an issue counts against the cap while it is `running`, whatever its agent is doing at that moment.
  Rationale: a running issue's agent is either working or about to be read; counting by state would let the queue start a new agent in the tick between an agent's stop and the read of its answer.
  Date/Author: 2026-10-21, Claude.

- Decision: an issue is done only on its agent's `SUPERSET_WORKER_DONE` envelope for its own key, read from the agent's transcript when the agent is idle; with no envelope, the manager sends one nudge asking for it, then counts the attempt as failed.
  Rationale: the roadmap's rule: a stop alone means "end of turn", not "task finished". The transcript holds the exact text, which the screen may wrap.
  Date/Author: 2026-10-21, Claude.

- Decision: a retry starts a new agent in the same workspace, one size up (`escalation` in `routing.json`), with the previous failure in its prompt; a second failure marks the issue `failed` and every issue that depends on it, directly or not, `blocked`.
  Rationale: roadmap P1.4 and M3 ("une relance, une taille au-dessus"); keeping the workspace keeps any partial work.
  Date/Author: 2026-10-21, Claude.

- Decision: the issue checker and envelope parser live in `packages/shared/src/plan-issues.ts`, a port of `ade/workflow/scripts/ade.ts`; the Phase 1 script keeps its copy.
  Rationale: the host cannot import from `ade/`, and the Phase 1 skills run without the fork's host.
  Date/Author: 2026-10-21, Claude.

## Context and Orientation

The host service (`packages/host-service`) is the per-machine server that the CLI, the desktop app and the relay call through tRPC (`src/trpc/router/router.ts` registers every router; new routers are additive and released clients never call them). `createApp` in `src/app.ts` builds the database, the agent store and the runtime managers (`PullRequestRuntimeManager`, `PageWatchManager`) and the per-request context.

Facts the queue relies on:

- `createCallerFactory(workspacesRouter)(ctx).create({ projectId, name, branch, baseBranch, skipBranchPrefix, tags })` creates a workspace (a git worktree under `~/.superset/worktrees/<project>/…`) and returns `{ workspace: { id, … } }`. Without `baseBranch` it starts from the project's default branch. A worktree's branch lives in the main repository, so a child created with `baseBranch: <parent branch>` starts from the parent's commits.
- `runAgentInWorkspace(ctx, { workspaceId, agent: "claude", prompt, model, effort })` (`src/trpc/router/agents/agents.ts`) starts Claude in a new terminal and returns `{ sessionId }`, the terminal id.
- `TerminalAgentStore` (`src/terminal-agents/store.ts`) holds one binding per agent terminal (`lastEventType`, `agentSessionId`, `endedAt`) and emits `"change"` after every hook event; `agentRunState(lastEventType)` from `@superset/shared/agent-status` maps it to `starting`, `working`, `blocked` or `idle`.
- `readHarnessTranscriptOffLoop({ agentId, sessionId, worktreePath }, maxChars)` (`src/terminal-agents/harness-sessions/read-off-loop.ts`) reads the agent's own transcript on a worker thread and returns `{ text }`.
- `sendAgentMessage({ terminalId, workspaceId, text, submit: true, terminalAgentStore, db, eventBus })` (`src/terminal/terminal.ts`) types a message into the agent's terminal.
- `parseLaunchRules`/`estimateAgentLaunch` (`@superset/shared/agent-launch-estimator`, M1) read `routing.json`; `HostServiceContext.launchRoutingFile` is its path.

No git command may run on the host's main loop (`src/no-main-loop-blocking.test.ts`); this plan runs none.

Milestone 2. In `packages/host-service/src/runtime/plan-runs/`: `store.ts` (`PlanRunStore`: `list()`, `save(run)`, atomic writes), `plan-run-manager.ts` (`PlanRunManager`: `importRun`, `list`, `get`, `start`, `cancel`, `setMaxParallel`, `tick`, `start/stop` of an interval), `index.ts`. `tick()` runs one at a time; for each run in `running` it: reconciles each running issue (agent gone → failed attempt; idle → read answer → done / blocked / nudge once / failed attempt), applies retries and blocking, then launches ready issues while running issues are fewer than `maxParallel`, and marks the run `done` when nothing is queued or running. Every change is saved before the next step.

Milestone 3. `src/trpc/router/plan-runs/` (`planRuns` router: `import`, `list`, `get`, `start`, `cancel`, `setMaxParallel`), registered in `router.ts`. In `createApp`: build the store and the manager with real effects and an internal context, add `planRuns` to `runtime` (`HostServiceRuntime` in `src/types.ts`), tick on every `terminalAgentStore` change and every 15 s, start after crashed sessions are resumed, stop on shutdown. CLI: `packages/cli/src/commands/plan/` with `import`, `run`, `status`, `list`, `cancel`; a host without the router answers a clear error.
